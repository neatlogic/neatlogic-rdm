# Issue 调用集成事件插件

`ISSUE_INTEGRATION` 属于 RDM 商业功能，支持创建、更新、状态变更和删除四种 Issue 事件。需求、任务、缺陷等应用通过同一 `IssueVo` 类型契约使用，GitLab 不可选。没有商业模块或授权失效时，配置接口、插件和实际执行均不可用；历史规则保留。

## 配置和变量

在应用的事件设置中新增“调用集成”，选择已启用的集成，再为其输入参数填写 FreeMarker 表达式。变量 Tag 点击复制，粘贴至表达式中，例如 `${DATA.name!}`。自定义属性按属性 ID 引用，避免属性改名破坏配置。模板读取可读字段，集成参数不做邮件 HTML 转义。

配置字段为 `integrationUuid`、`paramMapping`、`successCallbackList` 和 `failedCallbackList`。映射项包含 `name` 和 `expression`；两个回调列表保存子配置，并由插件提取到引擎管理的子树中，随根配置一次保存。子节点不得跨应用、重复或同时属于两个分支。

集成处理器声明固定输入规范时以处理器规范为准，否则读取集成的自定义输入参数。只允许映射输入参数；必填项、参数类型及模板语法在保存和执行时检查。数组等结构参数必须渲染为合法格式，不会在解析失败时退化为字符串。

编辑器使用以下商业元数据接口，均携带 `projectId`、`appId` 并复用事件配置权限和归属检查：

- `/rdm/event/issue/integration/list`：选择集成，仅返回选项字段。
- `/rdm/event/issue/integration/get`：通过 `integrationUuid` 获取输入参数元数据。
- `/rdm/event/issue/integration/variable/list`：获取当前应用可用模板变量。

这些接口不返回集成 URL、认证配置或请求头。编辑器、查看器在商业模块内通过通用 `ComponentManager` 注册。

集成专属配置映射校验、参数渲染与转换、请求发送及分支选择保留在 `IssueIntegrationEventHandler` 内部；Handler 仅公开插件契约方法。集成选项和详情 API 通过 `IssueIntegrationMetadataService` 接口查询，其实现与插件共用集成读取、可用性检查及固定／自定义输入规范解析，不恢复整套插件执行 Service。变量 API 和两个插件依赖共享的 `IssueEventTemplateService` 接口；配置 API 依赖 `RdmEventConfigService` 接口。三个实现分别命名为 `XxxServiceImpl`，仅实现标注 `@Service`，调用方通过 `@Resource` 字段注入接口。Factory 不承担专属元数据查询。

## 分支与事务

HTTP 2xx 执行成功分支，非 2xx 或调用异常执行失败分支；失败分支完成后，父节点仍失败，当前事件链停止。配置失效、模板渲染失败及商业能力关闭不进入失败分支。子动作顺序执行，禁用节点不产生业务动作，子动作失败立即停止。

邮件插件 `ISSUE_EMAIL` 可作为成功或失败子动作；集成插件本身首版只作为根插件。子动作通过框架 `triggerChild()` 调用，保留父子审计和独立事务。普通事件每步重新加载需求，删除事件使用触发快照。

插件直接接收并返回 `IssueVo`。集成响应不写入需求、不作为下一个插件的输入，也不引入 `prevEventResult`。事件审计只记录集成标识、集成审计 ID、状态码和分支；完整请求及响应沿用原集成审计能力。

外部调用及已经提交的子动作无法随父节点失败撤销。本插件不增加自动重试、调用间隔、响应写回或恰好一次执行保证；框架集成已有的超时等执行设置继续适用。不会自动写入生产规则。
